E11: Combine Bindings

@Published sink AnyCancellable Reactive Bindings Requires E5, E9

Problem

ViewModels communicate with ViewControllers via closure callbacks (onStateChanged, onPhotosUpdated). This works but requires manual wiring and doesn't compose well. Replace all closure-based bindings with Combine's @Published properties and subscriber-based bindings. This is a refactoring exercise — external behavior must stay identical.

What the Solution Looks Like

ViewModels expose @Published private(set) properties. ViewControllers subscribe with $property.receive(on: DispatchQueue.main).sink {} and store cancellables in a Set<AnyCancellable>. All closure properties and their invocations are removed.

Steps

Step 1 Refactor HomeFeedViewModel

Add import Combine. Replace:

  • var onStateChanged: ((FeedState) -> Void)? → @Published private(set) var state: FeedState = .idle
  • var onPhotosUpdated: (([PhotoCellViewModel]) -> Void)? → @Published private(set) var cellViewModels: [PhotoCellViewModel] = []

Remove all closure invocations — just assign to the properties directly. The @Published wrapper automatically notifies subscribers.

Step 2 Update HomeFeedViewController bindings

Add import Combine and private var cancellables = Set<AnyCancellable>(). Replace closure assignments with:

viewModel.$cellViewModels
    .dropFirst()  // skip initial empty value
    .receive(on: DispatchQueue.main)
    .sink { [weak self] viewModels in
        self?.applySnapshot(with: viewModels)
    }
    .store(in: &cancellables)

viewModel.$state
    .receive(on: DispatchQueue.main)
    .sink { [weak self] state in
        self?.handleStateChange(state)
    }
    .store(in: &cancellables)
Step 3 Refactor PinDetailViewModel

Same pattern: replace onStateChanged closure with @Published on the state and all output properties (imageURL, titleText, authorName, etc.).

Step 4 Update PinDetailViewController bindings

Subscribe to $state with a Combine sink. Update UI in the subscriber. Store cancellables.

Step 5 Update ViewModel tests

Replace closure-based assertions with Combine subscriptions:

var states: [FeedState] = []
sut.$state.sink { states.append($0) }.store(in: &cancellables)
sut.viewDidLoad()
try await Task.sleep(for: .milliseconds(200))
// assert on collected states

Verify all existing test cases still pass with the new binding mechanism.

Hint: Why dropFirst()?

@Published emits the current value immediately upon subscription. If your VC subscribes in viewDidLoad(), it'll get the initial .idle state or empty array right away. Use .dropFirst() when you only want to react to changes after the initial value.

For state, you might not want to drop first (to handle initial state). For cell view models, you usually do want to drop first (to avoid an empty snapshot apply).
