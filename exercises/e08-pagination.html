E8: Pagination

Infinite Scroll State Machine Pull-to-Refresh Loading Indicators Requires E6, E7

Problem

The feed only shows the first page of 20 photos. Add infinite scroll — when the user scrolls near the bottom, load the next page and append results. Show a loading spinner in the footer during pagination. Add pull-to-refresh to reset and reload from page 1.

What the Solution Looks Like

The ViewModel's state machine is extended with a .loadingMore state and loadNextPage() method. The VC detects proximity to the bottom via willDisplay and triggers the next page. A LoadingFooterView (supplementary view) shows during loads. Pull-to-refresh via UIRefreshControl resets to page 1.

Steps

Step 1 Extend the ViewModel state machine

Add .loadingMore to FeedState. Add loadNextPage():

  • Only fires from .loaded(hasMore: true) — ignored in all other states
  • Transitions to .loadingMore
  • Increments page, fetches, appends new cell VMs to existing array
  • If response count < page size → hasMore = false

Add didPullToRefresh():

  • Resets page to 1, clears cell VMs array
  • Transitions to .loading, fetches fresh data
  • Ignored if already in .loading state
Step 2 Create LoadingFooterView

A UICollectionReusableView subclass with a centered UIActivityIndicatorView. Register it as a supplementary footer view in the collection view's layout. Show/hide the spinner based on the ViewModel state.

Step 3 Wire scroll-triggered pagination

In collectionView(_:willDisplay:forItemAt:), check if the displayed item is within the last 4 items. If so and state is .loaded(hasMore: true), call viewModel.loadNextPage().

When new cell VMs arrive, build a new snapshot that includes all IDs (existing + new) and apply with animation.

Step 4 Add pull-to-refresh

Add a UIRefreshControl to the collection view. On .valueChanged, call viewModel.didPullToRefresh(). When state transitions away from .loading, call refreshControl.endRefreshing(). On refresh, apply the new snapshot without animation (full replacement).

Step 5 Update tests

Add to HomeFeedViewModelTests:

  • loadNextPage from loaded → transitions to loadingMore, page incremented
  • loadNextPage when already loading → ignored (no duplicate fetch)
  • loadNextPage when hasMore: false → ignored
  • didPullToRefresh → resets page, clears data, transitions to loading
  • didPullToRefresh during loading → ignored
  • didPullToRefresh from error → triggers reload

Success Criteria

LevelCriteria
MinimalScrolling to bottom loads more pages. Pull-to-refresh works. All tests pass.
