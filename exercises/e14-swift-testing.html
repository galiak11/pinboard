E14: Swift Testing Migration

@Suite @Test #expect XCTest Coexistence Requires E2-E13

Problem

The project uses XCTest throughout. Apple's Swift Testing framework offers a more modern, declarative syntax. Migrate all test files to Swift Testing while keeping one file (APIClientTests) in XCTest to demonstrate that both frameworks coexist in the same test target.

What the Solution Looks Like

All test files except APIClientTests.swift use Swift Testing: @Suite structs instead of XCTestCase classes, @Test instead of func test..., #expect instead of XCTAssert*. A TestBundleAnchor class in Fixtures.swift handles bundle loading for structs.

Syntax Reference

XCTestSwift Testing
class FooTests: XCTestCase@Suite("Foo") struct FooTests
func testSomething()@Test func something()
XCTAssertEqual(a, b)#expect(a == b)
XCTAssertTrue(x)#expect(x)
XCTAssertNil(x)#expect(x == nil)
XCTAssertNotNil(x)#expect(x != nil)
XCTFail("msg")Issue.record("msg")
XCTAssertThrowsError#expect(throws: E.self) { try ... }

Steps

Step 1 Understand the key differences

Before converting, understand what changes:

  • Swift Testing uses structs, not classes — no setUp()/tearDown(), use init() instead
  • @MainActor annotation on the struct for UI-related tests (coordinator tests)
  • Bundle(for:) needs a class — structs can't be passed. Create a TestBundleAnchor class
  • XCTest and Swift Testing run side-by-side in the same target — no configuration needed
Step 2 Add TestBundleAnchor to Fixtures

Since Swift Testing test types are structs, Bundle(for: type(of: self)) doesn't work. Add a class anchor:

private class TestBundleAnchor {}

enum Fixtures {
    static func loadFixture(_ name: String) -> Data {
        let bundle = Bundle(for: TestBundleAnchor.self)
        let url = bundle.url(forResource: name, withExtension: "json")!
        return try! Data(contentsOf: url)
    }
}
Step 3 Migrate HomeFeedViewModelTests as example

Convert this file first as a reference pattern:

// Before (XCTest)
import XCTest
@testable import PinBoard

final class HomeFeedViewModelTests: XCTestCase {
    func testViewDidLoad_triggersLoading() async {
        // ...
        XCTAssertEqual(states.first, .loading)
    }
}

// After (Swift Testing)
import Testing
import Combine
@testable import PinBoard

@Suite("HomeFeedViewModel")
struct HomeFeedViewModelTests {
    @Test func viewDidLoad_triggersLoading() async {
        // ...
        #expect(states.first == .loading)
    }
}

For Combine-based tests, use the same $state.sink + Task.sleep pattern.

Step 5 Keep APIClientTests as XCTest

Intentionally leave APIClientTests.swift as-is. It uses setUp()/tearDown() for URLProtocol.registerClass/unregisterClass, which maps naturally to XCTest lifecycle. This demonstrates coexistence.
