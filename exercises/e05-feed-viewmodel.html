E5: Home Feed Service & ViewModel

MVVM State Machine Service Layer Mocking Requires E2, E3, E4

Problem

Build the business logic for the home feed. A service layer fetches photos from the API. A ViewModel manages a state machine that tracks loading, success, and error states, and transforms raw API models into display-ready cell view models. Everything must be testable through protocol-based mocking.

What the Solution Looks Like

HomeFeedService fetching from .photos(page:). PhotoCellViewModel as a display-ready struct with formatted likes text and pre-calculated aspect ratio. HomeFeedViewModel with a FeedState enum driving outputs via closures. A mock service enabling comprehensive ViewModel tests.

Steps

Step 1 Create HomeFeedService

Define HomeFeedServiceProtocol with func fetchPhotos(page: Int) async throws -> [UnsplashPhoto]. Implement HomeFeedService that takes an APIClientProtocol and calls the .photos(page:) endpoint.

Register it on AppDependencyContainer — add a homeFeedService: HomeFeedServiceProtocol property.

Step 2 Create PhotoCellViewModel

Display-ready struct with: id: String, imageURL: URL, title: String, authorName: String, aspectRatio: CGFloat, likesText: String.

Create init(photo: UnsplashPhoto) that transforms the model:

  • imageURL = photo.urls.small
  • title = photo.description ?? ""
  • aspectRatio = CGFloat(photo.width) / CGFloat(photo.height)
  • likesText = formatted: 0 → "No likes yet", 1 → "1 like", 500 → "500 likes", 14500 → "14.5K likes"
Hint: Likes formatting 
static func formatLikes(_ count: Int) -> String {
    switch count {
    case 0: return "No likes yet"
    case 1: return "1 like"
    case 2..<1000: return "\(count) likes"
    default:
        let thousands = Double(count) / 1000.0
        return String(format: "%.1fK likes", thousands)
    }
}
Step 3 Create HomeFeedViewModel with state machine

Define FeedState enum: .idle, .loading, .loaded(hasMore: Bool), .error(String).

ViewModel properties:

  • Inputs: viewDidLoad(), didPullToRefresh()
  • Outputs (closures): var onStateChanged: ((FeedState) -> Void)?, var onPhotosUpdated: (([PhotoCellViewModel]) -> Void)?
  • Internal: current state, array of cell view models, current page number

viewDidLoad(): if idle, transition to .loading, call service, on success transform to cell VMs and transition to .loaded(hasMore: count == 20), on error transition to .error(message).

Use Task { @MainActor in ... } for async calls so outputs fire on main thread.

Step 4 Write tests

Create MockHomeFeedService: stores a stubbedResult and records call count/page.

HomeFeedViewModelTests:

  • viewDidLoad triggers loading → success populates cell VMs
  • viewDidLoad with error → transitions to .error
  • Empty response → .loaded(hasMore: false)
  • Cell view models correctly formatted

HomeFeedServiceTests: correct endpoint called, response mapped, errors propagated.

PhotoCellViewModelTests: likes formatting (0, 1, hundreds, thousands), aspect ratio (landscape, portrait, square), nil description fallback.

Hint: Testing async ViewModel with closures

Since the VM uses async internally, tests need to wait for state changes. Pattern:

var states: [FeedState] = []
sut.onStateChanged = { states.append($0) }
sut.viewDidLoad()
// Wait for async to complete
try await Task.sleep(for: .milliseconds(200))
#expect(states.contains(.loading))
#expect(states.last == .loaded(hasMore: true))

Success Criteria

LevelCriteria
MinimalViewModel state transitions work correctly. All tests pass.
ExtendedEdge cases: empty response → hasMore false, nil descriptions, likes formatting for all ranges (0, 1, hundreds, thousands).
